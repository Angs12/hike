## 1. CURRENT SHAPE (code facts, current tree)

### 1.1 The exact SUBSET test (`:3041-3054`)

Channel 2 denotes the WHOLE, UNREWRITTEN address in the pre-def state
(`denote_imm_exp addr st_before`, `:3041`) and:

- `Error _` → `false` (`:3042`); `WordSet.is_top` → `false` (`:3044`);
  `WordSet.is_bottom` → **`true`** (`:3045`, dead path — seeding harmless);
  `WordSet.is_infinite` → `false` (`:3046`);
- else bounded: seed iff the `[min_elem, max_elem]` hull lies inside the
  neighborhood (`:3048-3053`):
  `lo >= -65536 && hi <= 65536` (signed `Int64.compare`);
  `Word.to_int64` failure → `false` (`:3054`).

Precision fact (code-reading, exact): against an INTERVAL, the hull test is
EXACT — `set ⊆ [nlo,nhi] ⟺ min >= nlo && max <= nhi`. There is no
"hull over-approximates the subset test" loss. The only bounded finite sets
the test refuses are sets with a member genuinely outside ±64 KiB (plus the
`to_int64`-failure corner, unreachable at 64-bit address width).

### 1.2 Which shapes seed, which fall through

Shape gate: `stack_address_of_rhs` (`:2992-2998`) covers exactly four rhs
forms — top-level `Load`, top-level `Store` (`mem := mem with [a] <- d`),
and `Cast(_, _, Load|Store)` (covers the `pad:64[…]`/`extend:64[…]`/`low:32`
print forms that are `Bil.Cast`). Everything else — `Extract` of a load,
`Ite`/`Concat`/`Let`-wrapped or `BinOp`-nested memory ops (e.g. the vector
build `YMM0 := …pad:128[mem[0x2020]]`, `/tmp/opencode/cand13-union.bir:491`)
— falls to the `_` arm of `extract` (`:3109`) and gets NO entry in either
map. Verified live: that `mem[0x2020]` def (tid `00001447`) carries no tag
(`dune exec zz_scratch_probe/dump_tags.exe -- /tmp/corpus/union_overlap main`
prints `-` in its kind column).

Channel 1 (direct, `:3037`): `mentions_frame_var` (`:3024-3030`) — any ONE
free var of the address present in the pre-def state's frame relation
(`AI.frame_lookup`, `:343 AI.frame_of`). Widened frame-affine addresses
still seed; `Infinite` stays a live classification (spec §2.2;
`.scratch/restriction-removal/spec.md:99-104`).

Fall-through consequences (all verified in code):
- Unseeded def: absent from `offsets`/`k_ranges` → emitter `find_def_tag`
  = `None` + `has_vsa_info` = false → `create_exp` raw-memory fallback
  (`src/bil2llvm.ml:1005-1011`). Non-seeding is the sound fallback
  (spec §2.2 invariant, `spec.md:114-118`).
- Non-convergence arm (`src/hike_vsa.ml:78-89`): every memory op tagged

- No-memory-op subs skip the fixpoint entirely (`has_mem_ops`,

### 1.3 Two different denotations (load-bearing)

The seed test denotes the RAW address in `st_before` (`:3041`). The
classification denotes the REWRITTEN address (`rewrite_addr`, `:296-329`;
returns input unchanged on failure, `:327-329`) under the tag-state meet
(`st_tag_of`, `:3001-3017`) at `:3078-3085`, then `classify` (`:2957-2971`,
TOP→`Unbounded`) and `k_range_of` vs RSP (`:2985-2990`,
`addr − rsp`, `None` when either side is top/bottom).
Consequence used in §3: the classification denotation is a MEET-narrowing of
(tag-state ≈ block-entry state over) the seed denotation — narrowing cannot
create TOP from bounded (`X ⊑ B ∧ X = TOP ⟹ B = TOP`). So a
**seeded-but-`Unbounded` tag proves the seed-time denotation was already
TOP**, hence channel 2 necessarily refused that def and **channel 1 fired**
(the only channel that accepts TOP-denoting addresses). Deduction, not
instrumentation — the predicate itself is uninstrumented.

## 2. PAPER CHECK (WYSINWYX, TOPLAS 2010, doi 10.1145/1749608.1749612)

Primary source verified directly: author PDF
`https://research.cs.wisc.edu/wpis/papers/wysinwyx.final.pdf` (995 KB,
fetched 2026-09-04, text-extracted to `/tmp/opencode/wysinwyx.txt`, 4048
lines; §-level cites below are `wysinwyx.txt` line numbers).

- **§3 VSA (txt:721-796): backs "stored values are offset sets + indirect
  accesses need pointer value-sets".** "VSA … determines a safe approximation
  of the set of numeric values or addresses that each register and a-loc
  holds at each program point. In particular, at each instruction I that
  contains an indirect memory operand, VSA provides information about the
  contents of the registers that are used. This permits it to determine the
  (abstract) addresses that are potentially accessed" (txt:740-745). "A key
  feature of VSA is that it tracks integer-valued and address-valued
  quantities simultaneously" (txt:763-764). "An element of the abstract
  domain for VSA associates each a-loc with a set of (abstract) memory
  addresses and numeric values" (txt:773-775).
- **§3.1 Value-Sets (txt:797-830): backs "offset sets".** "Each abstract
  address is a pair (memory-region, offset)" (txt:798-799);
  `ValueSet = MemRgn → StridedInterval⊥` with
  `MemRgn = {Global} ∪ Proc ∪ AllocMemRgn` (txt:811-816); example value-set
  `(2[1,9], 8[−48,−40])` = global offsets + `AR_main` offsets (txt:818-824).
- **§4.1 "The Problem of Indirect Memory Accesses" (txt:1781-1830+): backs
  "indirect accesses need pointer value-sets".** "Unlike the operands
  considered in the Semi-Naïve algorithm, local methods do not provide
  information about what an indirect memory operand accesses… `[eax + 4]`
  may access a local variable, a global variable, a field of a heap-allocated
  data-structure, etc., depending upon what eax contains" (txt:~1816-1820).
  "A register used in an indirect memory operand may be initialized with a
  value read from memory… to determine the value of the register, it is
  necessary to know the contents of that memory location, and so on.
  Fortunately, [VSA] described in §3, can provide such information"
  (txt:1821-1826). Example 4.1 (`lea eax,[ebp-8]; mov [ebp-12],eax;
  mov [eax],1`, txt:1784-1805) IS the saved-address class
  (`touch`/`two_pass`/`sum_n`/`consume_mixed`).
- **Structural observation (follows from §3.1, flagged as synthesis, not
  paper text):** the paper's value-sets are `(region, offset)` pairs, so a
  stored frame address is KNOWN frame-resident by construction — the paper
  never needs an "is this offset in the frame" predicate. hike's
  single-address-space CLP must recover structurally-known residency
  through the SUBSET test. That is exactly why the SUBSET rule has no paper
  behind it:

**NO paper behind (stated plainly):** (i) SUBSET-vs-intersection —
no seeding gate of any kind exists in the paper (there is no
frame-neighborhood constant, no subset test; §4.2–4.3 go straight from VSA
value-sets to a-loc recovery); the invariant is hike's soundness policy
(spec §2.2, `spec.md:114-118`), agreeing with precision-note §5. (ii) The
±64 KiB constants — spec's own word is "recommendation" (`spec.md:109`);
nothing in §3–§4.1 suggests a magnitude. (iii) The bounded-only / refuse-
infinite / refuse-TOP arms of `is_seed` — engineering conservatism layered
on the paper's mechanism.

## 4. DESIGN SKETCH (no implementation; SUBSET invariant fixed in all three)

All options keep `is_seed`'s SUBSET-only contract (spec §2.2) and change
only WHAT is tested, never subset→intersection.

**Option A — accept Infinite-with-span-inside-neighborhood.**
Seam: the `is_infinite → false` arm (`cbat_vsa.ml:3046`). Rationale:
channel 1 already seeds `Infinite` ("`Infinite` stays a live
classification", spec §2.2) and the merge/span machinery already treats
`Infinite` by its `[min,max]` span (`span_of`, `:3115-3118`); a span ⊆
neighborhood carries the same frame-residency argument as a bounded set
with that hull. Exclusion (soundness): wrapped sets (`min > max` signed —
span covers the complement) must still refuse. Pinning tests (new
fixtures beside `mk_gpr_rbp_sub`, `test_cbat/test_vsa.ml:258`): (i) strided
infinite address with span inside ±64 KiB → seeds (positive — the rule
change); (ii) wrapped infinite → does NOT seed (negative — the exclusion);
(iii) existing P23-1/F1-2/E2eD-4 negatives unchanged. Expected prize on
measured evidence: zero (§3.1–3.2 contain no Infinite-refused defs).
