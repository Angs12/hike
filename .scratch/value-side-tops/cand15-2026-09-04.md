## 2. Paper check — CC 2004 + Weiser 1984 (section-level)

Sources: CC04 author PDF via the static.aminer.org mirror (full text
fetched; Springer page and `application/pdf` fetch both failed —
access caveat as in cand12 §2); Weiser via IEEE Xplore/CSL abstract +
DOI record (full text paywalled; section facts corroborated by the
standard teaching account, cited as such).

- **CC04 requires transformers for every instruction; no slicing
  pre-pass.** "The transformers for the various edges are listed in
  Fig. 4… Each transformer takes an abstract store and returns a new
  abstract store" (CC04 §4 per the mirror text; Edges carry the
  transformers, conditionals included). VSA is "an abstract
  interpretation of the executable to find a safe approximation for
  the set of values that each data object holds at each program
  point" — i.e., EVERY data object at EVERY point: the removed
  `denote_def` gate (M4) restores exactly this. "The analysis is not
  forced to give up all precision when a load from memory is
  encountered" — the paper's load rule resolves through the abstract
  store; topping a load result merely because the address is
  inconvenient is foreign to it.
- **CC04's crude variant is the TOP baseline.** "To contrast… we
  compared it with… crude value-set analysis, that always sets the
  value-sets for all non-register a-locs to [TOP]" (CC04 §6/Table 2
  per mirror). Every residual in §1 is a local relapse to crude-VSA
  behavior (gap-TOP, misaligned-TOP, entry-TOP): implementation gaps
  against the paper's discipline, not theory gaps.
- **CC04 entry state includes esp.** "The abstract store for the entry
  node consists of the information about the initialized global
  variables and the initial value of the stack pointer (esp)" (CC04
  §4). hike's `default_entry = AI.top` (`cbat_vsa.ml:2582`) keeps only
  the frame relation (`seed_frame`) and leaves esp's VALUE top — hike
  is strictly coarser than the paper at entry (context for sketch
  option B; the paper does not say esp ≡ 0, only that its init value
  is tracked).
- **CC04 calls have transformers; library calls are identity "as a
  temporary expedient".** ("As a temporary expedient, calls to library
  functions are treated during analysis as identity transformers"
  — CC04 §5.) hike's `denote_call` callback threaded but never
  applied at transfers (cand12 §1.2) is the same expedient, wider:
  the modify_copy sret-pointer TOP (§1.3) and the va_arg callee-input
  TOPs (§1.4, now zero as addresses) are the price of it —
  candidate-14 scope, explicitly NOT cand15.
- **Weak updates where soundness demands them.** "Assignments to
  [recursive-AR / heap] a-locs must be modeled by weak updates, i.e.,
  the new value-set must be unioned with the existing one, rather
  than replacing it" (CC04 §4, Fig. 4 case two). Relevant as a
  constraint on sketch option A (below): any load-reassembly must
  over-approximate; concretely-determined bytes may narrow TOP, never
  narrow a non-TOP set except by the existing join/meet rules.
- **Weiser TSE 1984 (SE-10(4), pp. 352–357,
  doi:10.1109/TSE.1984.5010248).** Slicing criterion = (statement n,
  variable set V); "Starting from a subset of a program's behavior,
  slicing reduces that program to a minimal form which still produces
  that behavior… guaranteed to represent faithfully the original
  program WITHIN THE DOMAIN of the specified subset of behavior"
  (abstract). Statement-minimal slices are in general unsolvable
  (abstract). For cand15: a syntactic pre-slice (the removed
  restriction) preserves behavior only within its criterion — arg-setup
  defs, index producers, and hidden-copy stores outside the criterion
  silently drop value flows. Full denotation is the paper-consistent
  discipline; the §1 residuals are all POST-denotation value
  problems, i.e. they live downstream of where Weiser stops applying.

Paper verdict per residual: union_overlap (load resolution — paper §4
Fig. 4 covers; gap is ours), array_local (same), sbv pair-loads
(a-loc byte assembly — paper's RIC/numeric domain covers; the
misaligned-TOP arm is ours), sbv sret + va_arg inputs (call
transformers — paper §5 covers in principle; ours are the
never-applied-`denote_call` expedient). All four are implementation
gaps under the papers' discipline, none a theory gap — with the
standing scope line: interprocedural inflow needs candidate 14, not
transfer-level work.

## 4. Design sketch — 3 transfer-level options (no implementation)

Seeding untouched by construction (all three sit strictly downstream
of `is_seed`/`denote_def`; `denote_def`, `extract`, and the
Channel-1/2 rules are not modified). Fallback preserved: any option
that cannot prove its precondition returns today's value bit-for-bit.

- **Option A — misaligned multi-cell load reassembly** (closes class
  3: 8 defs). In `Mem.find'` (`cbat_ai_memmap.ml:538-546`) replace the
  `else Val.top i` arm: split the load key at intersecting cell
  boundaries (the existing `Key.interval_diff` idiom, cf. cand12 shape
  A) and reassemble bytes in load order, casting each fragment with
  the `op_at`/`join_at` machinery (`:418`) already used on the aligned
  path. Soundness: fragments are the stored over-approximations of
  exactly the bytes read (CC04 weak-update constraint — narrow TOP
  only; never narrow a non-TOP set except through existing
  join/meet). Seam: `find'`/`fold_intersections` only. Pin test: unit
  fixture over `Cbat_ai_memmap` — two adjacent u32 cells `{0},{1}`,
  u64 load spanning both ⇒ value `{0 + 1·2^32}` (today: TOP);
  production pin: sbv-main probe `def_top` 13 → ~5 with `ldstk`
  unchanged and IR byte-identical (values only feed tags here).
- **Option B — entry-RSP value anchor** (measures classes 1/2/4 inflow;
  CC04 entry-esp license, §2). In `init_sol`/`default_entry`
  (`cbat_vsa.ml:2582-2594`) bind the entry RSP VALUE to `{0}` alongside
  the existing `seed_frame` offset-0 fact. Consistency argument: Mem
  keys are already entry-RSP-relative offsets (rewrite), living as u64
  in `[2^64−64K, 2^64)` — disjoint from canonical user addresses by
  the Channel-2 neighborhood design, so offset-valued RSP cannot
  collide with absolute heap addresses. Risk (stated): any absolute
  value joined into an offset set silently crosses spaces — measurement
  FIRST (probe `def_top` delta on straight-line subs like sbv-main;
  `ldstk`/IR-identity gates must not move), implementation only if the
  RSP-value paradox (§1.3 gap) resolves in its favor. Seam: entry
  construction only. Pin test: sbv-main `def_top` drops with zero
  `ldstk`/emission movement; a mixed absolute+offset join fixture keeps
  over-approximating (no narrowing ever).
- **Option C — store-through-TOP policy, documented non-prize**
  (modify_copy sret stores, `cbat_vsa.ml:385-386`). Today's silent
  no-op (`return_mem mv`) is precision-preserving but leans unsound
  (a TOP-address store may hit any cell); the sound alternative
  (clobber may-cells to TOP) is precision-negative. For cand15 the
  honest statement is that NEITHER arm has prize: bounding the address
  (options A/B, index work) automatically re-enables the stores, and
  the sret addresses specifically need interprocedural inflow (cand14)
  first. Sketch records the status quo + the audit flag, proposes no
  change. Pin test (guardrail, not prize): sret-store fixture asserts
  today's drop behavior so a future soundness fix registers its
  precision cost explicitly.

Out of scope (neighboring candidates, NOT cand15): interprocedural
param/return passing incl. `denote_call` application (14); escape-range
narrowing (12, cand12 shapes A–C); landmark/widening tuning at loop
heads (T02 audit); Channel-2 seeding changes (seeding untouched).
