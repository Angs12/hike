## 1. Current shape (code facts)

### 1.1 The escape-range computation — `call_abstraction_frame`

`src/cbat_vsa/cbat_ai_representation.ml:311-337`:

- Signature (`:311-312`): `preserved` (word lane) + `rsp : WordSet.t`
  (call-time RSP value set) + `escape : WordSet.t list` (one value set per
  escape source) + incoming env.
- Words lane (`:313` via `top_non_preserved`, `:300-305`): every word NOT
  in `preserved` is topped unconditionally — no escape involvement.
- `rsp_lo` (`:314-317`): `Some lo` iff `min_elem` and `max_elem` of the RSP
  set are both present AND equal — i.e. **RSP must be a singleton**.
- `escape_ranges` (`:318-328`): `None` if `rsp_lo` is `None`. Otherwise
  each escape value maps to its `(min, max)` word pair, EXCEPT a value
  that `is_top` or `is_infinite` (`:323`) or lacks min/max (`:324-325`)
  maps to `None`; if ANY entry is `None` (`:327`, length comparison) the
  whole `escape_ranges` is `None`. All-or-nothing per value list.
- Memories (`:329-336`): `Some lo` + `Some ranges` → per-mem-var
  `Mem.call_keep data ~keep_lo:lo ~escape:ranges` (`:332-335`), folding
  over `MemEnv` starting from the incoming env (per-cell keep, §1.3).
  **Any other combination → `MemEnv.top`** (`:336`) — the whole-memory
  kill. The fallback is total: one top escape value, one infinite escape
  value, or a non-singleton RSP discards the caller's ENTIRE memory map,
  including proven-local frame cells.

### 1.2 The call site — `denote_jump` / `inspect_call`

`src/cbat_vsa/cbat_vsa.ml:2484-2522`:

- `escape` (`:2495-2501`): `AI.find_word 64 env v` for each `v` in the
  block's `written` set — the CURRENT abstract value of each written reg
  at the call block (post-call-block-defs state, `postcond` at `:2560`).
- `written` comes from `call_facts_of_block` (`:2332-2339`): the
  intersection of `Abi.x86_64_sysv.int_param_regs` with the LHS vars of
  the block's defs — i.e. **only RDI, RSI, RDX, RCX, R8, R9**
  (`src/hike_abi/hike_abi.ml:26-27`) **that are WRITTEN in the call
  block** (static, syntactic, precomputed per block into
  `rc_call_facts` by `mk_rctx`, `:2351-2354`; read at `:2498` with a
  recompute fallback). Vector arg regs (YMM0-7), stack-passed args, and
  globals are NEVER in the escape set, even when they carry pointers.
- `pushed` (`:2337-2338`, read at `:2511-2513`): any def to RSP in the
  block gates the L-E1 +8 restore (`:2514-2521`); orthogonal to escape.
- `preserved` (`preserved_of_sub`, `:2621-2637`): SP, FP, callee-saved
  RBX/R12-R15 (`hike_abi.ml:33`) **plus every virtual var in the sub**
  (`:2625-2637`) — virtuals (lifter temporaries, `hike_stack`) always
  survive the words-lane top.
- Trap/syscall jumps (`Int _`, `:2526-2530`) use plain
  `AI.call_abstraction` (`:307-308`: `MemEnv.top` + top-non-preserved,
  frame relation kept) — whole-memory kill with NO keep attempt.
- `Call` with no return → `AI.bottom` (`:2486`); return-target mismatch
  → `AI.bottom` (`:2487`).
- Note: the interprocedural `denote_call` callback (`:2648-2673`) is
  threaded through `denote_jump` (`:2442`) but **never applied at a call
  transfer** — inside the `denote_jump` body (`:2447-2540`) the identifier
  occurs only in the signature (repo-wide `denote_call` grep 2026-09-04:
  only `:2442` sig, `:2554` sig, `:2572` pass-through as
  `denote_block_with_stores`' callback arg, `:2648` def, `:2669`
  recursive, `:2843`/`:2854` partial-app callback args). The chain is
  dead one step further than "unapplied at transfer": `:2843`/`:2854`
  construct `(denote_call stack)` callbacks that `denote_jump` never
  invokes, so the `:2648` engine itself has NO live entry caller and the
  nested callee fixpoint (`:2654`, `static_graph_vsa` recursion) never
  runs. Every call, internal or external, direct or indirect, is handled
  by the escape-proxy abstraction. There is no GMOD set (repo-wide
  `[Gg][Mm][Oo][Dd]` grep over `src/`: zero matches), no callee-exit
  merge on this tree.

### 1.3 Keep granularity — `Mem.call_keep` (per-cell keep, coarse kill test)

`src/cbat_vsa/cbat_ai_memmap.ml:481-502`:

- Per memory var, folds the interval tree (`IT.to_sequence`, `:497-500`):
  each CELL is independently kept or dropped — the keep itself is
  per-cell, not whole-memory.
- Drop rule (`:499`): drop iff `Key.lower k < keep_lo_pt` (cell starts
  below call-time RSP — caller's dead area, callee frame, heap, globals:
  all dropped regardless of escape) OR `in_escape k` (`:493-495`):
  `lower k >= lo && upper k <= hi` for some escape range — the cell must
  be **FULLY CONTAINED** in one escape range to be dropped.
- Two soundness-relevant observations (flagged, not fixed — this
  candidate is read-only):
  - (a) A cell PARTIALLY overlapping an escape range is KEPT in full,
    including the overlapped bytes the callee may write. The kill test
    points the unsound-leaning way; the sound rule kills on ANY overlap
    (with an optional remainder-split to recover the clean bytes — see
    §4 shape A).
  - (b) Unkeyable inputs keep the input map unchanged (`:491-492`,
    `| _ -> m`, and `:484` `None -> m`): an unkeyable `keep_lo` or
    escape point keeps EVERYTHING. `Key.of_word` fails only above 64
    bits or on non-concrete words (`:68-74`), unreachable for today's
    64-bit RSP/escape words, so the arm is dead-but-leaning-keep.
- Key order is `(width, unsigned value)` (`:38-41`); points are 64-bit
  (`:35-36`), so exotic widths cannot sneak past the comparisons.

### 1.4 When whole-memory-top fires (exhaustive on this tree)

1. `rsp_lo = None`: RSP non-singleton at the call (VLA/dynamic-RSP
   subs — `alloca_vla` class; multi-valued RSP from joins).
2. ANY escape value `is_top`/`is_infinite`/min-max-less
   (`:322-327`) — under restriction-removal this is now only the
   genuinely-unknown class (unwritten arg reg read as TOP is gone: arg
   defs are denoted, so values are real; a heap pointer is a bounded
   abstract address, not TOP).
3. `Int`/trap jumps — always (`:2526-2530`).
4. `MemEnv.top` also propagates from joining with any of the above;
   `call_abstraction` (plain) is otherwise unreachable on the call path.

## 2. Paper check — WYSINWYX §3, Figs. 9–11, MergeAtEndCall

Paper: Balakrishnan & Reps, "WYSINWYX: What You See Is Not What You
eXecute", ACM TOPLAS 2010, doi `10.1145/1749608.1749612`; author PDF
`https://research.cs.wisc.edu/wpis/papers/wysinwyx.final.pdf`.

could not be fetched in this environment (direct fetch of the author

quotes from the paper's/thesis's text layer via search (author PDF
`wysinwyx.final.pdf` + thesis `balakrishnan_thesis.pdf`, both on
`research.cs.wisc.edu/wpis/papers/`), quoted only where the excerpt is
a complete sentence; §3/Figs. 9–11 were NOT re-read end-to-end in this
session.

The paper's rule, in its own words:

- "The desired value for the exit→end-call edge is similar to in_x
  except for the value-sets of ebp, esp, and the a-locs of AR_C. The
  new out ∈ AbsEnv is obtained by merging in_c and in_x, as shown in
  Fig. 3.7." (thesis §3.5.2; the paper's twin sentence: "The new value
  of AbsEnv out is obtained by merging in_c and in_x, as shown in
  Fig. 11.")
- "In procedure MergeAtEndCall, the value-sets of all a-locs in in_x,
  except esp, ebp, and actual parameters, are propagated to the AbsEnv
  value at the end-call node." (thesis, Fig. 7.8 context.)
- "The value-set for ebp in out is obtained from the value-set for ebp
  from in_c (line 5 of Fig. 11)." + "esp at the end-call node is the
  abstract address (AR_main, −40). Note that this adjustment to esp
  corresponds to restoring the space allocated for actual parameters
  at the call-site" (paper p. 29 + thesis example).
- "A technique, called GMOD-based merging ([Balakrishnan 2007, Ch. 7]
  and [Reps and Balakrishnan 2008]), that increases the precision of
  abstract interpretation of procedure calls." (paper p. 67.)

Granularity verdict: the paper's rule is a **per-a-loc merge**, not a
whole-memory kill. Callee-exit value-sets propagate per a-loc to the
end-call node (refined to the GMOD set in the later variant); esp/ebp
and actual parameters keep caller values; every other caller a-loc
survives by default. There is no rule in the paper that tops the whole
abstract store at a call.

Where hike is COARSER than the paper:

- (i) Hike never analyzes the callee at transfer (§1.2: `denote_call`
  unapplied) — there is no exit-value refresh at all. Escaped cells are
  DROPPED (forgotten), not refreshed; non-escaped below-RSP cells
  (heap/globals) are dropped too. The paper refreshes callee-touched
  a-locs with callee-exit values; hike can only forget.
- (ii) The all-or-nothing fallback (`:336` → `MemEnv.top`) has no paper
  counterpart: one unknown escape address discards the caller's entire
  frame, where the paper's per-a-loc merge is unaffected by a single
  unknown a-loc.
- (iii) The below-RSP drop conflates the caller's dead stack area with
  live heap/global a-locs; the paper's regions keep them distinct.

Hike additions with NO paper behind them (engineering-only, agreeing
with `precision-2026-09-04.md` §5 ¶3): the written-regs escape scope
(only 6 int param regs, only if written in the call block — §1.2), the
singleton-RSP requirement (§1.1), the per-value all-or-nothing
`escape_ranges` construction (`:327`), the full-containment kill test
(§1.3), the `Int`-trap whole-memory kill (`:2526-2530`), and
virtuals-always-preserved (`:2625-2637`). The SUBSET-style soundness
noted in the prior doc is Channel-2 policy, unrelated to escape.

## 4. Design sketch — 3 sound per-cell shapes (no implementation)

Fallback preserved in all three: any shape that cannot prove its
precondition falls back to today's `MemEnv.top` (`cbat_ai_representation.
ml:336`) / `AI.call_abstraction` behavior bit-for-bit.

- **Shape A — kill-on-any-overlap + remainder split** (fixes §1.3(a),
  keeps all current precision, adds soundness). Change `in_escape` in
  `Mem.call_keep` (`cbat_ai_memmap.ml:493-495`) from full-containment to
  any-overlap (`Key.overlap`, `:100-101`), and split straddled cells:
  re-add the non-overlapping remainder via the existing
  `Key.interval_diff` machinery (same idiom as `op_add'`, `:449-466`).
  Soundness: callee writes ⊆ escape ranges (escape values are
  over-approximate addresses), so overlapped bytes may change (must go)
  and remainder bytes cannot (may stay). Seam: `Mem.call_keep` only;
  `call_abstraction_frame` untouched. Pin test: unit fixture over
  `Cbat_ai_memmap` — two adjacent 4-byte cells, escape range covering
  one cell plus one byte of the neighbor; assert the neighbor's 3 clean
  bytes keep pre-call values and the 4+1 overlapped bytes are gone
  (stronger than today: today all 8 bytes survive).
- **Shape B — `keep_lo := max_elem(RSP)` instead of fallback on
  bounded non-singleton RSP** (recovers the VLA-adjacent class).
  In `call_abstraction_frame` (`:314-317`), when the RSP set is bounded
  with min≠max, use `max_elem` as `keep_lo` rather than `None →
  MemEnv.top`. Soundness: the callee frame is built BELOW the actual
  call-time RSP; cells at/above EVERY possible call-time RSP (i.e. ≥ max)
  are the caller's in all cases. Cells in `[min, max)` are still
  dropped (today: everything). Escape `None`-forcing stays as-is.
  Seam: `rsp_lo` binding site only (`:314-317`); `call_keep` unchanged.
  Pin test: precision-probe-style fixture — sub with a 2-valued RSP at
  a call (e.g. join of pushed/non-pushed path) and a high frame cell;
  assert the high cell is exact post-call while mid cells go top (today:
  whole map tops).
- **Shape C — escape-set pruning of provably-non-frame values**
  (shrinks the kill set, never the keep rule). Before building ranges
  (`:322-326`), drop escape values whose set is disjoint from the frame
  window `[rsp_lo − frame_size, rsp_lo]`... — HONEST LIMIT noted in-task:
  on today's domain this fires almost never, because any value capable
  of forcing `None` (top/infinite) is by construction not provably
  disjoint, and bounded heap/global pointers ALREADY yield ranges that
  miss frame cells (so `call_keep` already spares them). Stated so the
  candidate does not over-claim: shape C is the principled per-value
  fallback decomposition, but its measurable prize on current artifacts
  is zero; it becomes load-bearing only if a future domain introduces
  partially-unknown pointer values (e.g. "unknown offset into known
  region"). Seam: range-builder `:322-328`. Pin test (forward-looking):
  call with one huge-but-bounded heap range arg + one frame-local cell;
  assert the frame cell survives (documents today's behavior as the
  no-regression pin; a future partially-unknown domain must keep it
  green while firing the new prune).

Out of scope (neighboring candidates, NOT cand-12): escaped-cell refresh
from callee-exit values / GMOD (§2(i) — needs the `denote_call`
callback applied at transfers, candidate-14 territory); stack-passed
arg / YMM escape-scope extension (soundness-positive, precision-
negative); below-`keep_lo` heap/global retention across calls (needs a
callee-write model, not an escape model).
